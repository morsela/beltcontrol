Belt Control — treadmill control in the browser

Using a WalkingPad without the KS+Fit app

You do not need an account, a phone, or the manufacturer's software to drive a KingSmith treadmill. The Bluetooth protocol it speaks is not authenticated, and a browser can speak it.

What you lose without the app, and what you don't

Most WalkingPad units ship with a small infrared or radio remote, and it is genuinely enough for walking: start, stop, faster, slower, mode. What the remote cannot do is remember anything. It shows no history, keeps no daily total, holds no goal, and the numbers on the pad's own panel reset the moment the session ends.

That memory is the real job of the phone app — and the price of it is an account, a login, push notifications, an SDK or two, and your walking data on somebody's server. For a lot of people that trade is a bad one, and it is the reason this page exists.

How the browser route works

Belt Control is a web page that uses Web Bluetooth — a browser API that lets a page talk to a Bluetooth Low Energy device directly, after you pick that device from a chooser the browser draws itself. There is no pairing code, no bridge, no companion service, and no server in the path. The radio link is browser to treadmill. The site that served the page only ever shipped static files and never sees a single reading.

In practice: open the page in Chrome or Edge, press Connect, pick your pad from the list. The app reads the treadmill's Bluetooth service table, works out which of the four known protocols it speaks, and drives it from there. Which treadmills that covers.

What you get

  • Start, stop and set speed, with the target and the belt's actual speed shown apart — a command that was written is not a belt that is moving.
  • Live distance, steps and calories, where the pad reports them honestly. Where it does not, you get an em dash rather than a number somebody made up.
  • Sessions detected automatically, with daily totals, a goal, a 30-day history and a consistency heatmap.
  • A lifetime odometer that survives the pad's own counter resetting.
  • Export to CSV, or a JSON backup you can carry to another browser.

Where the data lives

In localStorage, in the browser you used, and nowhere else. It is never uploaded, and there is no account to make. That has a real cost worth stating plainly: clear your site data and the history is gone, and a walk recorded on the desktop does not appear on the tablet. The backup export exists precisely because of that — it is the migration path, and it is on you to run it.

Nothing to install. Open it in Chrome or Edge with the treadmill switched on and in range.

Is it safe to drive a treadmill from a web page?

It is exactly as safe as driving it from the phone app, which is to say: the belt can start under software control with nobody standing on it, and that is true of every option on this page including the remote in your hand.

What the app does about it: starting and resuming both ask for confirmation and show the target speed; speed is clamped to the range the unit itself reports, and that clamp is clamped again so a pad reporting nonsense cannot widen it; Stop is always enabled, bound to Esc, and pinned on screen from the moment a start goes out until the belt reports zero; and the app never reconnects to a pad on its own, because silently reattaching to a possibly-moving belt is not a safe default.

Those reduce the risk rather than removing it. Closing the page does not stop the belt. Use the treadmill's own controls or safety key as the real stop.

Does it need the internet?

Only to load the page the first time. After that it installs an offline shell, so the app keeps working with the network down — the treadmill link never used the network in the first place.
