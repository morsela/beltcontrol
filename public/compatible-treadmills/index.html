Belt Control — treadmill control in the browser

Which treadmills work

Belt Control does not go by model name. It reads the treadmill's Bluetooth service table on connect and picks a driver from what it finds — so the question is not what your pad is called, it is which protocol its firmware speaks.

That distinction is not pedantry. The X21 appears in KingSmith's own product catalogue under two different chip families, and units sold under one model name have shipped with different radios in different years. A compatibility list keyed to model names would be wrong for somebody; probing the device is right for everybody. If your pad exposes one of the four services below, it will be driven correctly whatever the box said.

Full control means start, stop and set speed, with the app confirming each one against what the belt reports rather than against the fact that a command was written. A command that goes out and is ignored is a common failure on this hardware, and it is not treated as success anywhere in this app.

Pause is not universal

A pause is a stop the treadmill can be resumed from with its session counters intact. FTMS has a dedicated command for it — 08 02, resumed by the same op code that starts the belt — but no way to ask in advance whether a given unit supports it, so Belt Control sends it and reads the answer. A unit that rejects it gets stopped instead, says so, and the Pause button withdraws for the rest of the connection. A belt still moving under a button that says Paused is the outcome worth writing code to prevent.

On the KingSmith 0x1234 family, pause turned out to be the same bytes as stop — runState 0. What makes it a pause is that the pad keeps the session's counters across it and picks the walk back up on the next start, which a capture of the official app finally settled. The classic fe00 command set has no pause at all: it is not in the vendor's app, it is not in any published reverse-engineering of the protocol, and Belt Control does not guess one.

What "unverified" means

Some pads report a number that cannot be believed. On the 0x1234 family calories are a worked example: the pad does not measure them, it derives them from distance at a flat 62.5 gram-calories per metre. The scale is known and the arithmetic is right, but the figure is a formula's output, not a measurement, and it most likely tracks a body weight the pad never asked you for.

Fields like that are shown raw, flagged in the interface, and left out of every total rather than quietly summed into your week. A dashboard that adds up a number it does not trust is worse than one that shows an em dash.

Your browser matters more than your treadmill

Belt Control is built on Web Bluetooth, which not every browser implements. This is the constraint that actually stops people, and no amount of protocol support gets around it:

There is no way around the Safari gap, because on iOS every browser is Safari's engine underneath. The iPhone situation, in full.

The reliable way to find out is to try it. Nothing installs, no account is created, and the chooser only ever shows devices in radio range right now.

If your pad is not on the list

Try it anyway — the list above is the models that have been seen, not the models that work. Detection is by service table, so an unlisted pad on a known protocol simply works. If it lands on FitShow, or on nothing at all, the connection log names every service it looked for and what it found, and Send feedback in the app attaches that log to a mail. That log is the capture: it is how an undecoded pad gets decoded.
