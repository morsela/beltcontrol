Belt Control — treadmill control in the browser

WalkingPad on iPhone: the honest answer

Belt Control cannot run on an iPhone or an iPad, and no version of it ever will while the situation below holds. Here is exactly why, so you can stop looking.

Safari has no Web Bluetooth

Belt Control talks to a treadmill through Web Bluetooth, a browser API that lets a web page connect to a Bluetooth Low Energy device after you choose it from a browser-drawn chooser. Chrome shipped it in version 56, and Edge, Opera and Samsung Internet followed. Apple has never implemented it in Safari, and neither has Mozilla in Firefox — both declined it on privacy and security grounds, and neither position has moved.

On desktop that is an inconvenience: install Chrome. On iOS it is a wall, because of the second half.

On iOS, every browser is Safari

Chrome for iOS, Edge for iOS, Firefox for iOS and the rest are interface shells around WebKit — Apple's engine, the same one behind Safari. Installing Chrome on an iPhone does not install Chrome's engine, so it does not bring Chrome's Web Bluetooth with it. A page that needs the API gets the same answer in every browser on the device.

Regulatory pressure in the EU has begun to prise this open in principle, but no mainstream third-party engine has shipped to iOS users at scale, and none of it changes what your phone can do this afternoon.

What is actually left

  • A desktop or laptop. Chrome or Edge on Windows, macOS or Linux, with the machine in radio range of the pad. This is the setup Belt Control is designed around — most of these treadmills live under a desk with a computer already on it.
  • An Android phone or tablet. Chrome on Android has Web Bluetooth. Propped on the treadmill and installed to the home screen from the manifest, it behaves like an app.
  • A third-party WebBLE browser on iOS. A handful exist — they bundle their own Bluetooth bridge and expose the API to pages they load. They can work, but they are niche, paid, and not something to rely on.
  • The manufacturer's app, or the remote. KS+Fit is a native iOS app and uses the platform Bluetooth stack directly, which is precisely the thing a web page is not allowed to do. The bundled remote needs no phone at all.
This is a browser limitation, not a hosting one. Nothing about the treadmill, the protocol, or how this app is served can be changed to work around it — the API simply is not there to call.

History still works, everywhere

One thing does survive on an iPhone: the History screen. Import a JSON backup exported from a browser that can connect, and you can browse past walks, totals and the heatmap on any device, Safari included. You cannot start a belt from it — but the record travels.

On a desktop or an Android device? Then it works. Chrome or Edge, treadmill switched on and in range.
